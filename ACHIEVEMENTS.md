# Достижения (через лаунчер антологии)

Что добавлено в проект и как это проверить.

## Как это работает

Steam из игры **не поднимается**: App ID принадлежит антологии, и `SetAchievement`
вызывает её лаунчер. Игра только создаёт пустой файл с именем достижения:

```
<папка exe>/achievements/<API_NAME>
```

Лаунчер раз в секунду (и ещё раз при выходе из игры) читает эту папку, открывает
достижение в Steam и **удаляет файл**. То есть файл — это заявка, а не запись
о выданном достижении.

Steamworks.NET и любой Steam-SDK проекту не нужны, ничего подключать не надо.

## Достижения

| API Name | Когда выдаётся | Точка в коде |
|---|---|---|
| `PA_ENDING_WATCHED` | концовка Watched | `EndingProgress.MarkWatched()` |
| `PA_ENDING_UNCERTAIN` | концовка Uncertain | `EndingProgress.MarkUncertain()` |
| `PA_ENDING_ILL` | концовка Ill | `EndingProgress.MarkIll()` |
| `PA_WINDOW` | первый взгляд в окно | `WindowPanel.Show()` |

Концовки подключены там же, где игра записывает саму концовку, поэтому
`FinalSequenceManager` править не пришлось: все четыре ветки финала уже сходятся
в `RecordEnding()`.

API Name должен совпадать **байт в байт** со строкой в Steamworks, включая
регистр (`PA_WINDOW` ≠ `pa_window`). Заводит и публикует достижения владелец
антологии у своего приложения.

## Что где лежит

- `Assets/Scripts/Core/LauncherAchievements.cs` — весь механизм.
- `Assets/Scripts/Editor/AchievementsMenu.cs` — отладочное меню `Tools → Достижения`.
- `EndingProgress`, `WindowPanel`, `MainMenuUI` — по паре строк вызова.

## Мелочи, которые важны

- **Пометка о выданном достижении лежит в PlayerPrefs**, а не в папке заявок:
  файл лаунчер стирает, и по нему нельзя понять, выдано достижение или нет.
- **В главном меню заявки подаются заново** (`LauncherAchievements.ResubmitUnlocked`
  + `EndingProgress.SyncAchievements` в `MainMenuUI.Start`). Это покрывает два
  случая: концовка открыта ещё до появления достижений, и игра переехала
  в другую папку (PlayerPrefs общие на всю машину, а папка заявок — нет).
  Повторная заявка стоит одного `SetAchievement` на уже открытом достижении,
  Steam это игнорирует.
- **Лежащий файл не переписывается** — он ещё в очереди у лаунчера.
- Запись обёрнута в try/catch: если папка игры недоступна на запись, в консоль
  уйдёт предупреждение, но игра не сломается.

## Как проверить

В редакторе заявки падают в **корень проекта** (`Application.dataPath` — это
`Assets`, а рядом с exe в билде лежит `*_Data`). Поэтому:

1. `Tools → Достижения → Показать состояние` — видно пометку и лежащие заявки.
2. `Tools → Достижения → Сбросить локально` — чистит пометку и неотданные заявки.
3. Полностью схема проверяется только на Player-билде, запущенном из лаунчера.

Если файл не исчезает — это ожидаемо, пока API Name не заведено и не опубликовано
в Steamworks. Лаунчер в этом случае пишет «Unknown Steam achievement API name».
